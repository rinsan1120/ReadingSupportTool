# ReadingSupportTool

ブラウザで使う、暫定名「朗読支援ツール（仮）」の初版です。HTML・CSS・JavaScriptだけで動作し、ビルドや外部ライブラリは不要です。

- **文章を読む**：貼り付けた原文を保持し、横書き・自然な縦スクロールで表示します。文字数目安・行間・実表示行ごとの余白を調整できます。
- **朗読時間を調べる**：暫定例文12本または自分の文章で朗読速度を測り、作品全体の文字数から「約○分」を推定します。複数回の計測では、合計文字数÷合計秒数で速度を求めます。

## 起動

このディレクトリで次を実行し、<http://localhost:8000> を開きます。

```sh
python -m http.server 8000
```

`index.html` を直接開いても基本機能を利用できますが、保存機能やAPIの対応はブラウザによって異なります。画面点灯維持には対応ブラウザとHTTPS（またはlocalhost）が必要です。

## GitHub Pages

オーナーがpushした後、リポジトリの **Settings → Pages → Deploy from a branch** で `main` の `/ (root)` を選択します。公開先は通常 <https://rinsan1120.github.io/ReadingSupportTool/> です。ファイルはすべて相対パスで参照します。この初版の実装時にはpush・公開を行いません。

## 本文と保存

入力本文はアプリのメモリだけに保持し、外部送信・自動保存しません。「文章を読む」の本文と読み仮名はJSONファイルへ手動保存・読み込みできます。通常のアプリ内画面移動では残りますが、再読み込み・タブ終了でメモリ上の原稿は失われます。ブラウザ自身による入力欄の復元は保証・制御しません。

`sessionStorage` の `reading-support-results-v1` に保存するのは、読了した計測の文字数・秒数・種別と推定対象字数だけです。作品名・入力本文・例文本文・途中計測は保存しません。ストレージが使えない場合も、その画面を開いている間は利用できます。

文字数はUnicodeコードポイント単位で、空白・改行を除き、句読点・括弧を含めます。認識できる青空文庫形式のルビ・注記をカウント用の派生文字列だけから除外します。HTML由来のルビと手動追加ルビも、原文とは別に保持してカウントから除外します。完全な青空文庫パーサーではありません。作品全体の字数は手動で補正できます。

## HTMLルビの取り込み

青空文庫などのWebページでルビを含む文章をコピーし、空欄の本文入力欄へ通常の貼り付けをしてください。クリップボードの `text/html` にある `ruby`・`rt`・`rp`・`rb` を解析し、「元の読み仮名を○件取り込みました」と通知します。本文入力欄には読み仮名を除いた原文だけを表示し、朗読画面では標準の `<ruby>` で対象語の上に小さく表示します。[参考ページ「手袋を買いに」](https://www.aozora.gr.jp/cards/000121/files/637_13341.html)の形式に対応しています。時間計測用の本文入力欄でも取り込めます。

元の読み仮名は `sourceRubies` の `{ start, end, reading }` として保持します。`start` は対象語の先頭、`end` は末尾の直後のUTF-16オフセットで、どちらも書記素境界です。手動ルビとは独立した情報で、元ルビを手動ルビの編集UIから変更・削除する機能はありません。従来の淡い金色の `【読み仮名】` は共存でき、元ルビの対象語の途中に追加した場合は、対象語を分断しないよう語の直後に表示します。手動ルビの元の挿入位置は変更しません。

本文全体を選択してHTMLを貼り付ける場合は、現在の本文・両種類の読み仮名の置換を確認します。キャンセルや解析エラーでは何も変更しません。読み仮名を保持した原稿の途中へのHTMLルビ貼り付けは、位置ずれを避けるため受け付けず案内します。読み仮名がない本文の途中なら、追加した部分の位置を調整して取り込みます。通常のプレーンテキスト編集・貼り付けでは従来どおり、変更後の原稿を開く際に既存の読み仮名の削除を確認します。

`br` の改行、段落、空段落、全角空白を反映し、通常のHTMLの連続する半角空白は1つにまとめます。`pre` とインラインの `white-space: pre / pre-wrap / break-spaces` では空白・改行を保持します。抽出した本文と同時に位置を計算するため、改行や絵文字でルビ位置がずれることはありません。コピー元のスクリプト・画像・埋め込みは挿入せず、不活性なtemplate内から文字列だけを取得します。

クリップボードにHTMLがない場合（プレーンテキスト貼り付け、コピー元アプリがHTMLを提供しない場合）は元ルビを復元できず、従来のテキストとして扱います。入れ子・多段のルビ（`rtc` / `rbc` / `rbspan`）、対象語や読み仮名が欠けた部分コピー、改行をまたぐ対象語は取り込まず、理由を通知します。外部CSSによる改行・非表示制御や画像の外字も再現しません。1つの対象語は途中で折り返さないため、極端に長い対象語・読み仮名は表示幅を超える場合があります。ルビのある行は、低い行間設定でも隣接行に重ならないよう上部の余裕を確保します。文字サイズ・幅・行間・自動区切りの設定変更時は、本文の実表示行を再計測します。

## 朗読画面の読み仮名

「文章を読む」の上部で「ルビ：OFF」を押すと、ルビモードがONになります。文字の左半分をタップするとその直前、右半分をタップすると直後に、未登録の点線付き `【】` を表示します。入力欄に読み仮名を入れて「登録」を押すと、淡い金色の `【読み仮名】` として確定します。空白だけの登録はできません。登録後もルビモードはONのままです。

登録済みの読み仮名はルビモード中に選択して編集・削除できます。キーボードでも読み仮名にフォーカスしてEnter/Spaceで編集できます。「キャンセル」またはEscapeで未登録の変更を取り消します。OFF時の本文タップ、文字のない余白、ドラッグ・スクロールでは追加しません。入力ダイアログはVisual Viewportの変化に合わせて位置と高さを調整します。

原文と `{ offset, text }` の読み仮名一覧を別々にメモリ上で保持します。`offset` は**原文の先頭からのUTF-16コード単位数**で、DOM Range・既存の読書位置と同じ基準です。挿入できるのはIntl.Segmenterによる書記素の境界だけで、サロゲートペア・結合文字・ZWJ絵文字の途中には挿入しません。同じ位置には1件を保持し、既存の読み仮名を編集します。カウントには原文だけを渡すため、追加した読み仮名は文字数に影響しません。原文の `【括弧書き】` は色も文字数の扱いも変更しません。

同じ本文で朗読画面を開き直した場合は読み仮名を保持します。入力画面で本文を編集しても元の読み仮名は直ちには削除せず、変更後の本文を朗読画面で開く際に、すべての読み仮名が失われることを確認します。キャンセルすれば以前の本文と読み仮名の組を保持し、元の本文に戻して再度開けます。ルビモード自体は画面を開くたびにOFFから始まります。

読み仮名はStorageへ保存せず、再読み込み・タブ終了でメモリから失われます。「操作」メニューから、読み仮名を引き継いで同じ文章の時間計測へ進めます。時間計測画面を開いても「文章を読む」の読み仮名はメモリに保持します。

## 原稿のJSON保存・読み込み

「文章を読む」の朗読画面で「操作」→「原稿を保存」を押すと、表示中の原文と確定済みの読み仮名を `reading-manuscript.json` としてダウンロードします。読み仮名がない原稿も保存できます。保存先や同名ファイルの扱いはブラウザ・端末の設定に従います。保存処理はブラウザ内で完結し、サイトへの通信は行いません。

本文入力画面の「原稿ファイルを読み込む」からJSONファイルを選ぶと、検証後に本文・両種類の読み仮名・文字数を復元し、通常の朗読画面をルビモードOFFで開きます。手動ルビは同じ色と括弧、元ルビは対象語の上に表示します。手動ルビの追加・編集・削除、表示設定の変更、再保存ができます。文字数は読み仮名を含まない原文だけから計算します。

既存の本文・読み仮名がある場合は、検証に成功してから置き換えを確認します。キャンセル、不正なJSON、対応外のバージョン、読取エラーでは既存の原稿と入力中の本文を変更しません。空白だけの読み仮名、改行入りの読み仮名、範囲外・文字境界の途中の位置、同じ位置の重複も、ファイル全体のエラーとして理由を表示します。不正な項目の省略や位置の自動補正はしません。

UTF-8の保存形式はversion 2です。`text` は合成前の原文、各位置はその原文のUTF-16位置です。手動ルビの括弧も元ルビの読みも、原文へ書き込みません。従来のversion 1（`sourceRubies`なし）も読み込め、元ルビなしとして復元します。保存し直すとversion 2になります。

```json
{
  "format": "reading-support-manuscript",
  "version": 2,
  "text": "狐が森から現れた。",
  "annotations": [
    { "offset": 1, "text": "こぎつね" }
  ],
  "sourceRubies": [
    { "start": 0, "end": 1, "reading": "きつね" }
  ]
}
```

原文の改行・空白・日本語・絵文字と、読み仮名の内容を保持します。入力欄が改行をLFに正規化しても、未編集で再表示・再保存する間は元のCRLF/CRと位置を保持します。本文を編集して差し替えを承認した場合は、入力欄の内容が新しい原文になります。空行内を含め、既存モデルで許容される文字境界の読み仮名を表示します。JSON内の文字列はHTMLとして解釈しません。

元のファイルは自動更新しません。変更を残すには再度「原稿を保存」で保存してください。ファイルの読み込みや原稿の変更に伴う自動ダウンロード、Storageへの本文・読み仮名の保存、サーバー送信は行いません。計測履歴の既存保存方針も変わりません。

## 同じ文章で時間を計測

「文章を読む」の朗読画面で「操作」→「この文章で時間を計測」を選ぶと、本文と確定済みの読み仮名を引き継いで計測準備画面へ直接移動します。JSONから読み込んだ原稿でも利用できます。メニューを選んだだけでは計測を開始せず、「計測を始める」を押してから既存の3・2・1カウントダウンで開始し、本文の先頭から読み始められます。文字数が0の原稿は計測へ移動できません。

計測する文字数と結果に記録する文字数は、読み仮名を除いた原文から計算します。推定対象となる「時間を知りたい作品全体の文字数」は、引き継ぐたびに原文の文字数で初期設定します。以前の別作品の設定は流用しません。計測準備画面でもこの値を手動変更でき、入力画面・結果画面の値と連動します。本文幅・文字サイズ・行間・実表示行ごとの自動区切りは従来の設定を利用できます。

移動後は自動的に「用意した文章を読む」になり、計測用入力欄には原文だけを反映します。異なる本文が既に入力されている場合に限り上書きを確認し、キャンセル時は元の朗読画面と計測用入力内容を保持します。「入力へ戻る」から未変更の本文を再表示した場合も、読み仮名を同じ位置・色・括弧形式で保持します。CRLF/CRを含むJSON原稿も、未編集なら元のUTF-16位置を保持します。

計測側の原稿は既存のReadingAnnotationsを使った独立したコピーです。読み仮名は計測準備中・計測中とも読み取り専用で、タップしても編集を開始しません。計測用の本文を編集して準備画面を開く場合は、計測用の読み仮名の削除を確認します。キャンセルすれば入力中の本文と以前の読み仮名を保持し、本文を戻すと再び同じ原稿を表示できます。例文を選んだ間は引き継いだ読み仮名を表示せず、「用意した文章」に戻して本文が未変更なら保持した読み仮名を表示します。

計測側で本文を差し替えても、「文章を読む」の元の本文・読み仮名や元のJSONファイルは変更しません。元の原稿を再び開いて編集・JSON保存できます。計測結果は従来の「用意した文章」と同じ種別で記録し、履歴の保存形式・平均速度・推定時間の計算は変更していません。本文・読み仮名の自動保存や送信も行いません。

## 朗読台本のPDF出力

HTML由来の元ルビのPDF対応は今回の対象外です。既存のPDF出力処理は変更しておらず、元ルビの読みは印刷へ出力しません。本文と手動の `【読み仮名】` は従来どおり出力します。両種類の読み仮名を残すにはJSON原稿を保存してください。

「文章を読む」の朗読画面で「操作」→「PDF出力」を選ぶと、印刷用原稿を準備して案内を表示します。「印刷画面へ」を押し、ブラウザ・端末の印刷画面で「PDFとして保存」を選んでください。スマートフォンでは共有・プリントから保存する場合があります。アプリは印刷画面を開くだけで、保存完了を判定したり、PDFを自動ダウンロードしたりはしません。

A4縦・四辺15mmの余白を基本とします。印刷画面の用紙をA4、向きを縦、倍率を100%にし、ブラウザが付けるヘッダー・フッターをOFFにしてください。用紙・倍率・余白を印刷画面で変更すると、想定どおりの配置にならない場合があります。端末によって印刷機能やPDF保存の手順・対応状況が異なります。iOS/Safari・Androidの実機操作は未確認です。

画面の実測済みの表示行・文字位置と、原文・登録済みの読み仮名に対応するテキスト範囲から、専用の印刷レイアウトを生成します。画面のDOMを複製したり、画像として貼り付けたりはしません。白背景・黒い本文・濃い紺色の `【読み仮名】` とし、原文の括弧書きは黒い本文のままです。サイトの操作UI・案内・文字数・未登録の読み仮名は出力しません。読み仮名の編集中は登録またはキャンセルしてから出力してください。

折り返した行を固定し、画面の文字サイズ・行間・自動区切り・空行の相対関係を保持します。本文幅が用紙の印刷領域を超える場合は、文字サイズと座標を同じ倍率で縮小します。スマートフォンなどの狭い本文は拡大せず、用紙中央に配置します。印刷用紙の幅を基準に再折り返しは行いません。縮小後の文字サイズが9pt未満の場合は案内に警告を表示するため、必要に応じてキャンセルし、本文幅を狭くするか文字を大きくしてください。

行単位で改ページし、同じ読み仮名が含まれる複数行はまとめて同じページへ配置します。読み仮名が1ページより長い場合は、それも収まる倍率まで全体を縮小するため、非常に小さくなることがあります。その場合は読み仮名の短縮も検討してください。読み仮名のまとまりを次ページへ送ると、前ページの残りが通常より広くなる場合があります。ページ先頭では自動区切りの追加余白を重ねず、元の空行は可能な範囲で維持します。大量の空行がある場合は、空白ページを作らない範囲に余白を制限します。

印刷中は通常の朗読画面の再配置を抑え、印刷終了・キャンセル後は元の表示・読み仮名・設定と読書位置を保持します。原文・文字数・JSON形式は変更せず、Storageへの本文保存や外部サービスへの送信は行いません。JSONから読み込んだ原稿も同じ処理で出力します。

本文は可能な限りPDFのテキストとして残しますが、文字のコピー・検索はブラウザとフォントの出力にも依存します。Windows/Chromeで、明朝体の一部漢字が部首の互換字形コードとして抽出される例（黄→⻩など）と、カラー絵文字が検索用の文字として抽出できない例を確認しました。見た目が同じでも検索語が一致しない場合があります。[SkiaのPDF文字エンコーディングの説明](https://docs.skia.org/docs/dev/design/pdftheory/)も参照してください。複雑な双方向文字やフォント固有の字形処理まで完全に一致することは保証しません。

## 表示行の区切りと制約

`reader.js` が、原文と読み仮名を合成して自然に折り返したDOM上のRangeで表示行を測ります。5表示行ごと（初期値）のインライン範囲を相対移動して余白を作るため、固定文字数分割や強制改行は行いません。単独改行は数え続け、元の空行でリセットします。読み仮名が複数行・区切りにまたがる場合も同じ色と挿入位置を保持します。表示位置を原文のUTF-16位置に対応付け、読み仮名の追加・編集・削除や設定・横幅変更後に見ていた位置を可能な範囲で復元します。

インライン範囲の作成後に行位置を再検証し、折り返しに差異が生じた段落は自動区切りを適用せず、画面に状態を表示します。複雑な結合文字・双方向テキストやブラウザ固有のフォント処理では、同じ表示を保証できません。位置復元は行単位の近似で、文末付近・空行内・画面回転時などはスクロール範囲の制約を受けます。長文は必要なときだけ再計測しますが、極端に長い文章では初回描画や設定変更に時間がかかる場合があります。

計測中も幅変更に応じて再配置しますが、表示設定は変更できません。非表示通知（`visibilitychange`）・ページ離脱で進行中の回を無効にします。画面点灯維持はユーザー操作時だけ要求し、非表示・画面離脱・解除通知後は自動取得しません。端末の電源ボタン操作そのものは検出しません。

## ファイルと確認

- `index.html`：ホーム、入力、共通朗読画面、計測結果、設定ダイアログ
- `styles.css`：夜の紺・淡い青を基調にしたレスポンシブ表示
- `samples.js`：2026-10-19承認の暫定例文12本（原文・題名・改行を保持）
- `reader.js`：実レイアウト測定、余白、原文位置との対応、印刷用の行・テキスト位置情報
- `manuscript-print.js`：印刷専用レイアウト、用紙への縮小、読み仮名を保護したページ分割
- `reading-annotations.js`：原文と読み仮名の管理、書記素境界・JSON形式の検証と復元
- `html-ruby.js`：不活性なHTML解析、原文と元ルビ範囲の抽出
- `app.js`：画面切り替え、原稿の計測への引き継ぎ、文字数、原稿JSONのローカル保存・読み込み、計測、結果保存、点灯維持
