# よみじたく

「よみじたく」は、朗読支援サイトです。キャッチコピーは「声にする前の、ひと支度。」です。HTML・CSS・JavaScriptだけで動作し、ビルドや外部ライブラリは不要です。

- **原稿を準備する**：本棚で複数原稿を管理し、本文・ルビ・ペン・マーカー・メモを編集して、朗読・PDF出力に利用できます。
- **朗読速度を測る／朗読時間を見積もる**：12本の例文、自分の文章、本棚の原稿で朗読速度を計測し、平均速度から指定時間で読める文字数や作品の推定朗読時間を求めます。時間見積もりは計測結果から独立した画面でも利用できます。

## 起動

このディレクトリで次を実行し、<http://localhost:8000> を開きます。

```sh
python -m http.server 8000
```

`index.html` を直接開いても基本機能を利用できますが、保存機能やAPIの対応はブラウザによって異なります。画面点灯維持には対応ブラウザとHTTPS（またはlocalhost）が必要です。

## GitHub Pages

オーナーがpushした後、リポジトリの **Settings → Pages → Deploy from a branch** で `main` の `/ (root)` を選択します。公開先は通常 <https://rinsan1120.github.io/ReadingSupportTool/> です。ファイルはすべて相対パスで参照します。公開・デプロイはリポジトリの運用に従います。

## ユーザーデータ・保存・再開（2026-10-26時点）

起動時に「保存したデータから続きを始める」または「初めて使う・新しく始める」を選びます。1ブラウザにつき1ユーザー分の本棚を扱い、表示名は任意です。複数原稿の題名・本文・読み仮名・ペン・マーカー・メモ、直近100件の朗読速度履歴、作品全体文字数・予定朗読時間をまとめて管理します。ログイン・会員登録は不要です。

**データの正本は、利用者が明示的に保存するユーザーデータJSONです。** 原稿画面・画面上部・ホームの「保存」は、表示中の原稿だけではなくユーザーデータ全体を保存します。ブラウザへの**自動保存・自動ダウンロードは行いません**。作業中は画面内に保持され、未保存変更は状態表示とページ離脱時の警告（ブラウザが許す場合）で案内します。再読み込み・タブ終了後は保存済みJSONを選び直してください。

ファイル保存ダイアログに対応する安全なブラウザでは、保存先を選び、既存ファイルへの上書きを指定できます。非対応環境は通常ダウンロードとなり、実際の保存完了をアプリから確認できないため利用者へ確認を求めます。**ファイルを開いただけでは、以後の編集が自動的にファイルへ反映されるわけではありません。** 読み込みは現在のユーザーデータ全体を置き換え、自動統合はしません。

旧バージョンのブラウザ保存データが見つかった場合は、起動時に任意で引き継ぐか、旧データをそのまま取り出せます。移行しても元のブラウザ保存データは削除しません。以前の**原稿1件用JSON**は、本文入力画面の「旧形式の原稿ファイルを取り込む」から移行する方式です。端末間の自動同期・クラウド保存・外部送信はありません。

文字数はUnicodeコードポイント単位で、空白・改行を除き、句読点・括弧を含めます。認識できる青空文庫形式のルビ・注記をカウント用の派生文字列だけから除き、HTML由来・手動の読み仮名は原文とは別管理です。作品全体の字数は手動補正できます。

### 本棚と独立した朗読時間見積もり

ホームの本棚では、原稿の追加・選択・題名変更・削除ができます。題名、文字数、更新日、本文の冒頭、速度履歴があれば推定時間を表示します。削除には確認があり、ファイルへ反映するには保存が必要です。原稿上限は500件です。

ホームの「朗読時間を見積もる」画面では、本棚の原稿を選ぶか文字数を入力し、計測履歴から算出した平均速度で推定時間を求めます。履歴がない場合は先に朗読速度を測る導線を表示します。

## 原稿画面のツールバー

原稿画面の上段は「戻る」と、対応端末で表示される「画面点灯維持」です。主要操作は「白背景」「表示設定」「書込メニュー」「計測」「保存」「PDF」の順で直接操作できます。画面点灯維持はボタンからON/OFFし、非対応環境では表示されません。

PCでは操作を横並びにし、スマートフォンでは「戻る／点灯維持」の上段と主要操作の下段をまとめて表示します。スマートフォンで本文を下方向へスクロールすると両段とも隠れ、上方向へスクロールすると再表示されます。書き込み中や設定画面の表示中など、操作が必要な状態では従来どおり隠しません。PCではスクロールによる自動非表示は行いません。モードごとに利用できない機能は表示しません。

従来の「操作（…）」メニューとメニュー内の「ホームへ戻る」は廃止しました。「表示設定」は主要操作から直接開き、「点灯維持」は上段から独立して切り替えます。「文章を読む」「朗読速度の計測」「選択した例文のタイトル」は原稿画面のツールバーには表示せず、画面識別に必要な見出し情報だけを支援技術向けに残します。例文名などの計測対象情報は計測準備画面で確認できます。

## 白背景

原稿画面の主要操作にある「白背景：OFF」を押すとONになり、本文・書き込み欄を一体の白い背景と濃い文字で表示します。PC・スマートフォン共通で、主要操作は「白背景｜表示設定｜書込メニュー｜計測｜保存｜PDF」の順です。書込メニュー展開中も利用できます。もう一度押すと通常の暗い表示へ戻り、確認ダイアログは表示しません。操作バーやダイアログは従来の配色を維持します。

「白背景」の切り替えは配色だけを変更します。本文幅・折り返し・文字サイズ・行間・区切り・読書位置や書き込み位置は変えません。手動ルビは青色（#2563EB）、元ルビは本文と同じ濃色、ペンは選択した赤・青・緑、文字メモは共通の白系背景とメモごとの色、マーカーは黄色・水色・ピンクを識別できる淡い色になります。

「この文章で時間を計測」ではON/OFFも引き継ぎ、計測準備・カウントダウン・計測中・同じ本文での再計測まで維持します。準備中は上部の「白背景」ボタンから変更できますが、計測開始後は既存どおり変更できません。別の本文や例文を初めて開く場合は暗い表示から始まります。計測側で切り替えても「文章を読む」側の表示状態は変わりません。

この状態は現在のタブのメモリだけに保持し、ページの再読み込み後はOFFです。JSONには保存せず、原文・文字数・書き込みデータ・計測履歴にも影響しません。PDFはON/OFFにかかわらず手動ルビを従来の濃紺色とする白背景の印刷専用レイアウトを使い、印刷終了・キャンセル後も画面の表示状態を保持します。

## HTMLルビの取り込み

青空文庫などのWebページでルビを含む文章をコピーし、空欄の本文入力欄へ通常の貼り付けをしてください。クリップボードの `text/html` にある `ruby`・`rt`・`rp`・`rb` を解析し、「元の読み仮名を○件取り込みました」と通知します。本文入力欄には読み仮名を除いた原文だけを表示し、原稿画面では標準の `<ruby>` で対象語の上に小さく表示します。[参考ページ「手袋を買いに」](https://www.aozora.gr.jp/cards/000121/files/637_13341.html)の形式に対応しています。時間計測用の本文入力欄でも取り込めます。

元の読み仮名は `sourceRubies` の `{ start, end, reading }` として保持します。`start` は対象語の先頭、`end` は末尾の直後のUTF-16オフセットで、どちらも書記素境界です。手動ルビとは独立した情報で、元ルビを手動ルビの編集UIから変更・削除する機能はありません。従来の淡い金色の `【読み仮名】` は共存でき、元ルビの対象語の途中に追加した場合は、対象語を分断しないよう語の直後に表示します。手動ルビの元の挿入位置は変更しません。

本文全体を選択してHTMLを貼り付ける場合は、現在の本文・両種類の読み仮名の置換を確認します。キャンセルや解析エラーでは何も変更しません。読み仮名を保持した原稿の途中へのHTMLルビ貼り付けは、位置ずれを避けるため受け付けず案内します。読み仮名がない本文の途中なら、追加した部分の位置を調整して取り込みます。通常のプレーンテキスト編集・貼り付けでは従来どおり、変更後の原稿を開く際に既存の読み仮名の削除を確認します。

`br` の改行、段落、空段落、全角空白を反映し、通常のHTMLの連続する半角空白は1つにまとめます。`pre` とインラインの `white-space: pre / pre-wrap / break-spaces` では空白・改行を保持します。抽出した本文と同時に位置を計算するため、改行や絵文字でルビ位置がずれることはありません。コピー元のスクリプト・画像・埋め込みは挿入せず、不活性なtemplate内から文字列だけを取得します。

クリップボードにHTMLがない場合（プレーンテキスト貼り付け、コピー元アプリがHTMLを提供しない場合）は元ルビを復元できず、従来のテキストとして扱います。入れ子・多段のルビ（`rtc` / `rbc` / `rbspan`）、対象語や読み仮名が欠けた部分コピー、改行をまたぐ対象語は取り込まず、理由を通知します。外部CSSによる改行・非表示制御や画像の外字も再現しません。1つの対象語は途中で折り返さないため、極端に長い対象語・読み仮名は表示幅を超える場合があります。ルビのある行は、低い行間設定でも隣接行に重ならないよう上部の余裕を確保します。文字サイズ・幅・行間・自動区切りの設定変更時は、本文の実表示行を再計測します。

## 原稿画面の読み仮名

「文章を読む」の原稿画面で「書込メニュー」を開いて「ルビ」を選ぶと、読み仮名編集モードになります。文字の左半分をタップするとその直前、右半分をタップすると直後に、未登録の点線付き `【】` を表示します。入力欄に読み仮名を入れて「登録」を押すと、淡い金色の `【読み仮名】` として確定します。空白だけの登録はできません。登録後もルビ編集モードは続きます。

登録済みの読み仮名はルビモード中に選択して編集・削除できます。キーボードでも読み仮名にフォーカスしてEnter/Spaceで編集できます。「キャンセル」またはEscapeで未登録の変更を取り消します。書込メニューを閉じているときの本文タップ、文字のない余白、ドラッグ・スクロールでは追加しません。入力ダイアログはVisual Viewportの変化に合わせて位置と高さを調整します。

原文と `{ offset, text }` の読み仮名一覧を別々にメモリ上で保持します。`offset` は**原文の先頭からのUTF-16コード単位数**で、DOM Range・既存の読書位置と同じ基準です。挿入できるのはIntl.Segmenterによる書記素の境界だけで、サロゲートペア・結合文字・ZWJ絵文字の途中には挿入しません。同じ位置には1件を保持し、既存の読み仮名を編集します。カウントには原文だけを渡すため、追加した読み仮名は文字数に影響しません。原文の `【括弧書き】` は色も文字数の扱いも変更しません。

同じ本文で原稿画面を開き直した場合は読み仮名を保持します。入力画面で本文を編集しても元の読み仮名は直ちには削除せず、変更後の本文を原稿画面で開く際に、すべての読み仮名が失われることを確認します。キャンセルすれば以前の本文と読み仮名の組を保持し、元の本文に戻して再度開けます。原稿画面を開いたときは書込メニューが閉じ、読み仮名編集モードは解除された状態です。

読み仮名は明示的なユーザーデータJSON保存で保持できますが、自動保存はしません。未保存の変更は再読み込み・タブ終了で失われます。原稿画面の「計測」ボタンから、読み仮名を引き継いで同じ文章の時間計測へ進めます。時間計測画面を開いても「文章を読む」の読み仮名はメモリに保持します。

## 書き込み（Issue #1・第1段階の試作）

「文章を読む」で「書込メニュー」を押すと、本文上部に書き込みツールを表示して編集できます。展開中も上部のボタンを表示し、再度押すかメニュー右上の「×」で閉じられます。開閉状態はボタンの背景・枠で示します。ペンは赤・青・緑を選択でき、太さは固定です。マーカーは従来の3色を選べます。書き込みは試作機能ですが、**ユーザーデータ全体のJSONで本文・読み仮名と一緒に保存・復元できます**。自動保存はせず、未保存の変更は再読み込み・タブ終了で失われます。原文・元ルビ・手動ルビとは別の `ManuscriptMarks` で管理し、文字数には含めません。

- **ペン**：本文の文字付近からマウス・指でドラッグして線を描きます。上段は「ペン｜マーカー｜メモ｜ルビ｜消去｜戻す」の順です。「ペン」選択中だけ下段に「赤｜青｜緑｜移動」を表示します。赤が初期値で、色ボタンを押すとその色の描画モードへ切り替わり、移動モードを解除します。別ツールから戻っても最後の色を保持し、描画済みの線は変色しません。短い斜線や読みの区切り向けで、タップだけでは線を作りません。
- **移動**：「ペン」の下段で「移動」を選び、いずれかの色の線をタップして一筆を選択し、ドラッグして線全体を移動します。移動中も上段のペンを選択表示し、下段メニューを維持します。描画とは排他的で、線の色は維持します。細い線の周囲にも当たり判定があり、選択した線には控えめな強調を表示します。線以外では通常の縦スクロールができます。マーカー・メモは移動対象外です。
- **マーカー**：ツール選択時だけ表示する「黄色・水色・ピンク」から色を選び、最初の文字から最後の文字へなぞって原文の書記素単位の範囲を半透明で強調します。初期色は黄色で、選択状態は名称と枠で示します。逆向きや複数行の範囲も扱い、色変更で既存マーカーの色は変えません。色の意味は自由に決められます。手動ルビの挿入位置の直前の原文文字を含む場合は、【読み仮名】全体も同じ色で背後から強調します。直後の原文だけを含む場合は、その手動ルビを強調しません。折り返しや複数行のルビにも対応し、保存済みのマーカーにも適用します。原文のUTF-16範囲とJSON形式は変更しません。
- **文字メモ**：書込メニューを開いた状態・「メモ」選択中に本文をタップし、200 UTF-16文字以内・改行可のメモを登録します。1回タップで選択し、もう1回タップで文章を編集します。選択中の右上の×は削除確認を表示し、キャンセルすると選択を保ちます。メモ以外の場所をタップすると選択を解除します。本体と丸い足先は独立してドラッグでき、ドラッグ直後には編集を開きません。
- **メモの設定**：選択中はマーカーと同じ3色ボタンで個別の色を変更できます。「メモ設定」で全メモ共通の文字サイズ（12〜28px、初期16px）と全体の不透明度（20〜100%、初期90%）を変更できます。固定幅180px・高さ自動・自動折り返しで、文字・枠・足・足先を同色、背景を共通色で描画します。
- **消しゴム**：線・マーカーをタップして1件を削除します。重なっている場合は新しい書き込みから削除します。文字メモの削除はメモツールの×を使います。
- **元に戻す**：書き込みの追加・削除・ペン移動・メモ文章編集・本体移動・足先移動・色変更を直近40操作まで戻せます。ドラッグ開始〜終了で1操作です。共通設定と読み仮名編集はこの履歴の対象外です。

書込メニューを閉じると通常のスクロール・本文選択へ戻ります。登録済みの書き込みは閉じた後も閲覧でき、同じ原稿を入力画面から開き直しても保持します。ペン描画・マーカー・消しゴムを選んでいる間、本文上の指のドラッグはスクロールに使いません。スクロールには書込メニューを閉じるか、「移動」の線以外の場所を使用してください。文字メモツールでは縦スクロールも可能で、ドラッグはメモの追加と誤認しません。ルビ編集はメニュー内のルビツールで行い、ペンなどの描画とは切り替えて使用します。ツール切り替え、モード終了、画面非表示、再配置、描画中のスクロールでは未確定の線・範囲を破棄します。

メモは本文上へ重ねて配置し、本文の表示幅や文字サイズを変えません。本文・他のメモとの重なりは利用者が調整します。足先は原文の文字位置と相対座標を保持し、文字への見た目の吸着は行いません。足先を動かす際は近くの文字を新しい基準にし、本体の位置を保ちます。レイアウト変更後は基準文字からおおよその位置へ再配置し、本体が画面幅の外へ出る場合は表示位置だけを補正します。書込メニューを閉じた状態や計測画面では編集・移動できません。

マーカーは原文のUTF-16範囲、メモは原文位置と相対変位、ペンは基準文字の原文位置と描画時の文字サイズを単位とする相対座標を保持します。`reader.js` の原文に対応する文字の実測矩形を利用し、本文のDOMには書き込み要素を挿入しません。通常の表示行計測・自動区切り・空行・ルビ描画・読書位置復元と独立したSVG/メモレイヤーです。

ペンの線は色を問わず、幅・文字サイズ・行間・区切り・読み仮名が変わっても非表示にせず、基準文字へ一筆全体を平行移動します。線の形・大きさ・太さを保ち、表示設定の変更だけでは保存点列を変更しません。設定変更前には「赤ペンの位置がずれる場合があります。変更後は移動して調整できます。」と確認します。同じ設定画面を開いている間、承認後の再確認は行いません。ずれた線は移動ツールで調整してください。移動確定時に近くの基準文字・点列・周辺文字情報・配置識別情報を更新し、1回のドラッグをUndoの1操作として記録します。Escape・ポインター取消・再配置・モード終了などで移動を取り消した場合、元の情報を保持します。複数選択・回転・拡大縮小・点単位編集はありません。

本文の差し替え・HTMLルビ付き本文の全置換・JSON原稿の読み込みでは、未保存の書き込みが失われることを既存の確認画面に追記します。キャンセル・読み込みエラーでは保持します。位置を保証できない途中へのHTMLルビ貼り付けも、書き込みがある場合は受け付けません。「この文章で時間を計測」では、両種類の読み仮名と全書き込みを独立コピーし、計測画面で閲覧専用に表示します。「文章を読む」の書き込みとUndo履歴は戻ったときにも残ります。

確定済みの3色ペン・マーカー・文字メモはJSON保存に加え、PDFにも出力できます。移動後の確定位置もPDFへ反映し、レイアウト不一致だけを理由に線を除外しません。描画位置や用紙内への収容を確認できない場合は理由を示してPDF準備を中止します。自動保存・同期は未対応です。計測履歴もユーザーデータJSONに保存し、書き込みは外部送信しません。

## ユーザーデータJSONと旧原稿形式

現在の通常保存形式は `format: "yomijitaku-user"`、`version: 1` です。表示名、原稿の一覧・原稿ごとの読み仮名と書き込み、直近100件の計測履歴、時間見積もり条件をまとめたものです。ファイル全体の上限は約30MiB、原稿は500件まで。不正データや非対応形式を検出した場合は、既存の作業を変更しません。

```json
{
  "format": "yomijitaku-user",
  "version": 1,
  "profile": { "name": "" },
  "manuscripts": [],
  "activeId": null,
  "history": [],
  "target": "",
  "plannedMinutes": "20"
}
```

これは新規ユーザーデータの空の例です。各原稿の本文・注釈は `manuscripts` 内に格納されます。

### 旧形式の原稿1件JSON（移行用）

従来の `reading-support-manuscript` 形式は、現在の「保存」では作成されません。本文入力画面の「旧形式の原稿ファイルを取り込む」で、原文・元ルビ・手動ルビ・確定済みの書き込みを取り込めます。置換確認のキャンセル、検証・読取エラー時は現在の原稿を保持します。取り込み後はユーザーデータ全体を保存してください。

以下は**旧形式v4の移行・互換用参考仕様**であり、通常のユーザーデータJSON全体の形式ではありません。

UTF-8の保存形式はversion 4です。`text` は合成前の原文、各位置はその原文のUTF-16位置です。手動ルビの括弧も元ルビの読みも、原文へ書き込みません。従来のversion 1（本文・手動ルビ）とversion 2（元ルビも含む）も読み込め、書き込みなしとして復元します。version 3の旧メモは内容・指し先を保持し、黄色の吹き出しへ簡易変換します。旧配置の完全互換はありません。旧原稿データは取り込み時に内部のversion 4形式で扱われます。通常の「保存」はユーザーデータJSON v1として出力し、書き込みがない原稿モデルも `marks: []` を含みます。

```json
{
  "format": "reading-support-manuscript",
  "version": 4,
  "text": "狐が森から現れた。",
  "annotations": [
    { "offset": 1, "text": "こぎつね" }
  ],
  "sourceRubies": [
    { "start": 0, "end": 1, "reading": "きつね" }
  ],
  "marks": [
    { "id": 1, "type": "marker", "start": 0, "end": 1, "color": "yellow" }
  ],
  "memoSettings": { "fontSize": 16, "opacity": 0.9 }
}
```

`marks` は種類ごとに次の確定データを保持します。原文の文字境界は読み仮名と同じ書記素境界です。

- ペン（`pen`）：`id`、`color`（`red`・`blue`・`green`）、`offset`（基準文字の先頭）、`points`（`{x,y}` の点列）、`witnesses`（`{offset,x,y}` の周辺文字位置）、`layoutKey`（描画・移動時の配置識別情報）、`fontSize`（描画単位のpx値）。色を省略した既存線は赤として復元し、保存時に色情報を含めます。不正な色は読み込み・保存時に拒否します。座標は基準文字の中心から記録した文字サイズを単位とした相対値です。version 4を維持し、`fontSize`がない旧version 3・4の線は既定の22px単位で復元します。旧ファイルには描画時の文字サイズがないため、当時22px以外で描いた線の大きさは近似となります。
- マーカー（`marker`）：`id`、`start`、`end`（原文の半開区間）、`color`（`yellow`・`lightblue`・`pink`）。色は1件ごとに保持し、色指定のない旧version 3は黄色として扱います。未知の色や型の不一致はファイル全体のエラーとし、現在の原稿は変更しません。version 1〜3の読み込みと、既存の件数・位置・座標・ID検証も維持します。
- 文字メモ（`memo`）：`id`、`offset`（基準文字の先頭）、`dx`・`dy`（本体左上）、`tx`・`ty`（足先）、`color`、`text`。座標は基準文字の中心から本文フォントサイズを単位にした相対値です。メモは改行可・空白だけでない200 UTF-16文字以内です。全メモ共通の文字サイズと不透明度はトップレベルの `memoSettings: {fontSize, opacity}` に保存します。

ファイルは10MiB、原文は200,000 UTF-16文字、各読み仮名配列は10,000件、書き込みは1,000件までです。ペンは色を問わず1本につき2〜2,000点と1〜2,000件の補助位置、原稿全体で計100,000点・補助位置までとし、相対座標は±1,000以内の有限数に限定します。IDは重複しない正の安全な整数です。上限超過は保存・読み込みともエラーにし、切り捨てません。

本文の表示設定は保存しません。メモの共通文字サイズ・不透明度は保存します。復元先の幅・折り返し・行間が異なる場合も3色のペンを表示し、基準文字に追従させます。必要に応じて移動ツールで配置を調整できます。

原文の改行・空白・日本語・絵文字と、読み仮名の内容を保持します。入力欄が改行をLFに正規化しても、未編集で再表示・再保存する間は元のCRLF/CRと位置を保持します。本文を編集して差し替えを承認した場合は、入力欄の内容が新しい原文になります。空行内を含め、既存モデルで許容される文字境界の読み仮名を表示します。JSON内の文字列はHTMLとして解釈しません。

旧形式の取り込み元ファイルは自動更新されません。変更を残すにはユーザーデータ全体の「保存」が必要です。ブラウザ自動保存・外部送信は行いません。

## 同じ文章で時間を計測

「文章を読む」の原稿画面で「計測」を選ぶと、本文・確定済みの読み仮名・赤・青・緑のペン・3色のマーカー・文字メモを引き継いで計測準備画面へ直接移動します。JSONから読み込んだ原稿でも利用できます。ボタンを押しただけでは計測を開始せず、「計測を始める」を押してから既存の3・2・1カウントダウンで開始し、本文の先頭から読み始められます。文字数が0の原稿は計測へ移動できません。

原稿画面から始めた計測の結果画面では、結果画面で「原稿に戻る」を選ぶと、本文・読み仮名・書き込み・表示設定を保った元の原稿画面へ戻ります。本文の表示位置も可能な範囲で復元します。ホームの「朗読時間を調べる」から始めた計測では、「入力した文章に戻る」または「計測設定に戻る」から計測入力へ戻ります。過去の計測履歴を開いた場合も計測入力画面へ戻ります。

計測する文字数と結果に記録する文字数は、読み仮名を除いた原文から計算します。推定対象となる「時間を知りたい作品全体の文字数」は、引き継ぐたびに原文の文字数で初期設定します。以前の別作品の設定は流用しません。計測準備画面でもこの値を手動変更でき、入力画面・結果画面の値と連動します。本文幅・文字サイズ・行間・実表示行ごとの自動区切りは従来の設定を利用できます。

移動後は自動的に「用意した文章を読む」になり、計測用入力欄には原文だけを反映します。異なる本文が既に入力されている場合に限り上書きを確認し、キャンセル時は元の原稿画面と計測用入力内容を保持します。「入力へ戻る」から未変更の本文を再表示した場合も、読み仮名を同じ位置・色・括弧形式で保持します。CRLF/CRを含むJSON原稿も、未編集なら元のUTF-16位置を保持します。

計測側は既存のReadingAnnotationsとManuscriptMarksを使った独立したコピーです。ID・原文位置・ペンの点列と補助情報・ペン色・マーカー色・メモ本文を保持します。読み仮名と書き込みは計測準備中・カウントダウン中・計測中とも閲覧専用で、追加・編集・削除・Undoは起動しません。文字メモは押せるボタンにせず、通常のスクロールを妨げません。結果画面から同じ本文で再計測しても保持します。画面幅変更後も3色のペンは基準文字へ追従し、形と大きさを保って表示します。計測中の手動移動はできません。

計測用の本文を編集して準備画面を開く場合は、計測用の読み仮名・書き込みの削除を確認します。キャンセルすれば入力中の本文と以前のモデルを保持し、本文を戻すと再び同じ原稿を表示できます。差し替えを承認した別本文には古い書き込みを表示しません。例文を選んだ間は引き継いだ読み仮名・書き込みを表示せず、「用意した文章」に戻して本文が未変更なら再び表示します。「文章を読む」側の編集やUndoが、計測用コピーへ影響することもありません。

計測側で本文を差し替えても、「文章を読む」の元の本文・読み仮名や保存済みユーザーデータJSONファイルは変更しません。元の原稿を再び開いて編集し、ユーザーデータ全体を保存できます。計測結果は「用意した文章」と同じ種別で履歴に記録され、ユーザーデータJSONで保存できます。平均速度・推定時間の計算は従来どおりです。本文・読み仮名の自動保存や送信も行いません。

## 朗読台本のPDF出力

HTML由来の元ルビは、PDFでも対象の漢字・語句の上に表示します。手動追加の `【読み仮名】` と区別し、両方の読み仮名と自由書き込みを同時に出力できます。貼り付け直後とJSONから復元した原稿を同じ処理で扱い、原文や保存形式は変更しません。

「文章を読む」の原稿画面で「PDF」を選ぶと、印刷用原稿を準備して案内を表示します。「印刷画面へ」を押し、ブラウザ・端末の印刷画面で「PDFとして保存」を選んでください。スマートフォンでは共有・プリントから保存する場合があります。アプリは印刷画面を開くだけで、保存完了を判定したり、PDFを自動ダウンロードしたりはしません。

A4縦・四辺15mmの余白を基本とします。印刷画面の用紙をA4、向きを縦、倍率を100%にし、ブラウザが付けるヘッダー・フッターをOFFにしてください。用紙・倍率・余白を印刷画面で変更すると、想定どおりの配置にならない場合があります。端末によって印刷機能やPDF保存の手順・対応状況が異なります。iOS/Safari・Androidの実機操作は未確認です。

画面の実測済みの表示行・文字位置と、原文・登録済みの読み仮名に対応するテキスト範囲から、専用の印刷レイアウトを生成します。画面のDOMを複製したり、画像として貼り付けたりはしません。白背景・黒い本文・濃い紺色の `【読み仮名】` とし、原文の括弧書きは黒い本文のままです。サイトの操作UI・案内・文字数・未登録の読み仮名は出力しません。読み仮名の編集中は登録またはキャンセルしてから出力してください。

元ルビは親文字・読み・原文範囲と画面での占有範囲をスナップショットに保持し、標準の `<ruby>`・`<rt>` で黒く描画します。縮小によるフォントの丸め差を測定して読みの位置を補正し、親文字と読みを分断しません。ルビの高さを含めて改ページし、3色ペン・マーカー・メモも同じ行の配置結果に従います。印刷のために書き込みを再解釈したり非表示へ切り替えたりはしません。ペンの選択表示や移動用の当たり判定は出力しません。

折り返した行を固定し、画面の文字サイズ・行間・自動区切り・空行の相対関係を保持します。本文幅が用紙の印刷領域を超える場合は、文字サイズと座標を同じ倍率で縮小します。本文幅からはみ出す長い元ルビも含めた幅を確保するため、追加で縮小する場合があります。スマートフォンなどの狭い本文は拡大せず、用紙中央に配置します。印刷用紙の幅を基準に再折り返しは行いません。縮小後の文字サイズが9pt未満の場合は案内に警告を表示するため、必要に応じてキャンセルし、本文幅を狭くするか文字を大きくしてください。元ルビの文字は本文の約半分のサイズなので、小さくなる場合は印刷前にご確認ください。

書き込みは確定済みの `ManuscriptMarks.items` と原文の文字位置から、本文と同じ行配置表に対応付けます。通常画面のSVG・メモDOMは複製せず、未確定の線や入力中のメモ変更は出力しません。JSONから復元した書き込みも同じ処理で扱います。

- **ペン**：通常画面と同じ基準文字への追従と移動後の確定位置を使用し、赤・青・緑の各色で全筆をベクトルとして出力します。座標・線幅は本文と同じ倍率で縮小します。ページをまたぐ線は元の行領域で分割して各ページへ変換し、ページ上下端の線幅分も確保します。描画範囲や用紙境界を検証し、収容できない線がある場合は省略せずにPDF準備を中止して理由を示します。
- **マーカー**：原文の文字範囲から各行の文字矩形を再構築し、個別の黄色・水色・ピンクを白背景向けの淡い色で本文の背後に配置します。手動ルビも画面と同じ条件で【読み仮名】全体を背後から強調し、改ページ後も色と対象範囲を保持します。隣接する対象外の文字や元ルビの読みへは広げません。
- **文字メモ**：指し先と同じページへ吹き出し・足・足先を描画し、個別の色と共通の文字サイズ・不透明度を反映します。吹き出し全体（文字・余白・枠・足・足先）を本文と同じ縮小率で出力し、画面で調整した相対的な位置と大きさを維持します。右側の専用欄は設けず、メモの有無で本文の幅・縮尺・改ページは変わりません。印刷領域を超える場合だけ本体・足先の位置を補正します。本文や他のメモとの重なりは許可し、PDF用の編集画面はありません。

非常に多い改行や大きい文字サイズで縮小後のメモ単体の高さが1ページを超える場合は、文字サイズ・改行を減らす案内を表示してPDF準備を中止します（初版の制約）。メモの衝突解消や自動分割は行いません。長いペンの線が本文幅を超える場合は従来どおり線を含む幅に合わせて本文を縮小するため、文字サイズの警告を確認してください。

行単位で改ページし、同じ読み仮名が含まれる複数行はまとめて同じページへ配置します。読み仮名が1ページより長い場合は、それも収まる倍率まで全体を縮小するため、非常に小さくなることがあります。その場合は読み仮名の短縮も検討してください。読み仮名のまとまりを次ページへ送ると、前ページの残りが通常より広くなる場合があります。ページ先頭では自動区切りの追加余白を重ねず、元の空行は可能な範囲で維持します。大量の空行がある場合は、空白ページを作らない範囲に余白を制限します。

印刷中は通常の原稿画面の再配置を抑え、印刷終了・キャンセル後は元の表示・読み仮名・書き込み・選択ツール・書き込みモード・Undo履歴・設定と読書位置を保持します。原文・文字数・JSON形式は変更せず、Storageへの本文保存や外部サービスへの送信は行いません。本文とメモはテキスト、線とマーカーはベクトルとして出力し、原稿全体を画像化しません。

本文・元ルビの読み・メモは可能な限りPDFのテキストとして残しますが、文字のコピー・検索はブラウザとフォントの出力にも依存します。上下のルビや横のメモが混在するため、PDF閲覧ソフトによってコピー時の文字順が異なります。Windows/Chromeで、明朝体の一部漢字が部首の互換字形コードとして抽出される例（黄→⻩など）と、カラー絵文字が検索用の文字として抽出できない例を確認しました。見た目が同じでも検索語が一致しない場合があります。[SkiaのPDF文字エンコーディングの説明](https://docs.skia.org/docs/dev/design/pdftheory/)も参照してください。複雑な双方向文字やフォント固有の字形処理まで完全に一致することは保証しません。

## 表示行の区切りと制約

`reader.js` が、原文と読み仮名を合成して自然に折り返したDOM上のRangeで表示行を測ります。5表示行ごと（初期値）のインライン範囲を相対移動して余白を作るため、固定文字数分割や強制改行は行いません。単独改行は数え続け、元の空行でリセットします。読み仮名が複数行・区切りにまたがる場合も同じ色と挿入位置を保持します。表示位置を原文のUTF-16位置に対応付け、読み仮名の追加・編集・削除や設定・横幅変更後に見ていた位置を可能な範囲で復元します。

インライン範囲の作成後に行位置を再検証し、折り返しに差異が生じた段落は自動区切りを適用せず、画面に状態を表示します。複雑な結合文字・双方向テキストやブラウザ固有のフォント処理では、同じ表示を保証できません。位置復元は行単位の近似で、文末付近・空行内・画面回転時などはスクロール範囲の制約を受けます。長文は必要なときだけ再計測しますが、極端に長い文章では初回描画や設定変更に時間がかかる場合があります。

計測中も幅変更に応じて再配置しますが、表示設定は変更できません。非表示通知（`visibilitychange`）・ページ離脱で進行中の回を無効にします。画面点灯維持はユーザー操作時だけ要求し、非表示・画面離脱・解除通知後は自動取得しません。端末の電源ボタン操作そのものは検出しません。
